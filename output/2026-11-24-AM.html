5. Shirudo: OpenAI and Cisco's open-source runtime for shielding unpatched Linux

Article
OpenAI and Cisco are launching Shirudo, an open-source runtime that helps teams protect Linux systems while they roll out patches. In a controlled test(opens in a new window), a Codex-generated shield blocked a Java4Shell exploit attempt against a running Elasticsearch service without requiring a restart.
We’re inviting developers, security researchers, and infrastructure operators across the industry to help develop the project further. The project brings together OpenAI’s frontier AI, security and infrastructure research and Cisco’s infrastructure and security expertise to help protect the systems people rely on every day.
Testing and deploying a patch can still take days or weeks. Protecting a service in the meantime can be challenging because an exploit and a legitimate request may rely on the same Linux operation. Blocking that operation entirely could take the service offline.
Shirudo (Japanese for “shield”) is designed to help security teams navigate this tradeoff. Teams can test whether a temporary safeguard, called a shield, blocks the behavior that exposes a vulnerability while allowing legitimate requests through. Once an operator approves the shield, it can be deployed while the service continues running.
Shirudo uses eBPF, a Linux technology that allows small programs to run at specific points inside the operating system. This makes it possible to observe suspicious activity and apply targeted security protections to running systems.
OpenAI and Cisco are designing Shirudo around four core capabilities:
- Live protection: eBPF shields can block vulnerable code paths without restarting the system. Security teams can monitor how a proposed shield would affect applications before enforcing it.
- Defense at machine speed: OpenAI and Cisco are designing Shirudo to give agents programmable controls to investigate vulnerabilities, develop targeted shields, and validate their effectiveness against exploits and real workloads. Security teams control what gets deployed.
- Trusted deployment: Shields are cryptographically signed and verified before loading. Linux's eBPF verifier checks eBPF programs against its safety rules, while kernel security controls restrict unauthorized changes.
- Hardware-backed verification: Shirudo uses a Trusted Platform Module (TPM) to support a verifiable record of protections being loaded or removed. Operators can use this evidence to check whether systems meet their security requirements.
The Shirudo technical walkthrough(opens in a new window) from the Linux Plumbers Conference shows how to apply a shield and verify it on the target host(opens in a new window). The Java4Shell vulnerability is another example illustrating how a targeted shield can protect a running application while a permanent patch is being prepared. Using OpenAI's Codex, the team generated a shield that added an input check to Java's Base64 decoder and attached it directly to a running Elasticsearch process. When attempting to exploit the vulnerability, the shield rejected the malicious input, blocking the attack while Elasticsearch continued running. You can read more here(opens in a new window).
Shirudo is a first step toward infrastructure that can adapt to emerging threats while remaining reliable. We want to strengthen the operating system foundations needed to deploy these protections at scale, including hardening the kernel and core services, limiting workload permissions, and making updates and recovery safer.
Our long-term goal is to enable defenders and AI agents to quickly identify affected systems, validate protections, and deploy eBPF shields that block exploits without disrupting workloads. Applications should run with only the permissions they need, governed by policies that are automatically generated and maintained.
We will combine frontier AI with security and infrastructure research to discover vulnerabilities and test defenses against realistic attacks. We aim to make it easier for operators to detect and contain compromises, prevent attackers from moving across systems, and restore services to a verified, known-good state. Hardware-backed attestation and independent network controls provide additional assurance even if individual systems are compromised.
OpenAI and Cisco are open-sourcing Shirudo(opens in a new window) so developers, security researchers, and infrastructure operators can inspect the code, test protections, and contribute to its development. Shirudo is licensed under BSD 2-Clause, with its BPF programs dual-licensed under BSD and GPL.
Our goal is to make tested shields available alongside vulnerability disclosures, giving operators a way to evaluate and deploy temporary protections while preparing permanent patches.

Questions
Where does my data live?
In one folder on your computer, ~/crm unless you choose another. Every company, contact and conversation is its own plain text file, and Hermit saves a version each time something changes, so any mistake can be undone. Technically: Markdown files in a git repository, and git revert goes back.
What are Markdown and git?
Markdown is a simple text format that any editor can open, so your records are never locked inside Hermit. Git is a free tool that remembers every version of your files. Hermit uses both so that you can read your data without Hermit and undo any change. You never have to type a git command yourself.
Does anything leave my Mac?
Only what you set up or ask for. Mail you approved, once you turn sending on. A private git backup, if you add one. The AI tool you ask, when you use Ask Hermit, enrichment, routines or outreach drafts. A public web page, when you add a company from its address or let outreach research one. Your mailbox and calendar, if you connect them. And a once-a-day version check with no identifiers, which you can turn off.
Do I need to be a developer?
No, but you do need an AI coding tool such as Claude Code, Codex or Cursor to install it, or you can install it by hand with Python and git. Your AI tool runs the commands and tells you in plain words what it is doing. On a fresh Mac you click Install once in an Apple dialog.
Does it run on Linux?
Yes, but it is less tested than on a Mac. The install is the same: your AI tool checks for git and Python and installs what is missing, which on Linux may ask for your password. There is no keychain on Linux, so the mail password is kept in a file only your user account can read.
Which AI tools work?
For the install, any AI coding tool that can read a file and run commands: Claude Code, Codex, Cursor, Gemini CLI, Grok Build and others. Afterwards, Claude Desktop, ChatGPT, Cursor or any other MCP client can read your pipeline and log interactions. An AI tool that wants the whole manual can read the docs, or the same text as one file in llms-full.txt.
Does it work with my email and calendar?
Yes, without OAuth. BCC or forward mail to an address such as you+crm@gmail.com and it is logged on the right contact. Past meetings come in from your calendar’s secret ICS link (Google, Outlook or iCloud). You type the app password and the link into the Settings page yourself, so they never pass through an AI chat.
Can my team use it?
No. Hermit CRM is built for one person. If you need a team CRM, use one of the others.
How does it compare with HubSpot, Attio or Pipedrive?
Those are hosted CRMs for teams, priced per seat, with your data in their cloud. Hermit CRM is free, for one person, and keeps your data on your own computer. Hermit CRM compared puts it side by side with HubSpot, Attio, Pipedrive, folk, Twenty and Notion, and says when each one is the better choice.
Does it run on Windows?
Not yet. Hermit CRM runs on macOS, and on Linux where it is less tested.
What does it cost?
Nothing. It is free and open source under the Apache License 2.0. It comes with no warranty and no support; see DISCLAIMER.md in the download.

Japan’s three largest automakers have agreed to begin standardizing vehicle parts in an effort to reduce costs, according to Automotive News. The outlet reports that Japan Automobile Manufacturers Association chairman Koji Sato, who is also the vice chairman of Toyota, announced the decision at a news conference in Tokyo this week.
In the short term, the standardization efforts will begin with unified quality criteria for steel, consistent protocols for plastics and resins, and a universal color-coding scheme for wiring harnesses. In the long term, the Japan Automobile Manufacturers Association has plans to move to more components that cover the entire car. The three areas were chosen as the first to be standardized because they are parts that are generally not noticed by consumers, and they shouldn’t have an impact on any brand’s individual identity. All three are also areas that account for significant production costs for the automakers, meaning they can have an immediate impact.
The first discussions of standardization are set to include Japan’s domestic automotive parts suppliers, though international suppliers will be brought into the fold in time. The first standardization efforts are set to go into place next year, according to the AN report.
The push to simplify and lower costs comes as Japan’s seven automakers, including Toyota, Nissan, Honda, Mazda, Subaru, Mitsubishi, and Suzuki, work to fend off the increasingly competitive list of Chinese automakers. The automakers are said to hope that they can channel the money saved by homogenizing into new innovations.
“We all share this strong sense of crisis, creating a momentum for change,” Sato said. “Based upon our sense of a crisis, we decided to choose these three areas.”
