The mobile shell, rewritten in Rust: wire-compatible with mosh 1.4, with a native Windows client and real scrollback.
Install · Known limitations · Usage · Compatibility · How it works · How this was built · Contributing
mosh-rs is an independent project. It is not affiliated with MIT, Keith Winstein, or the mosh maintainers. It exists because of their work: see License and attribution.
mosh is a remote terminal that survives what kills ssh: Wi-Fi to cellular handoffs, a laptop that sleeps overnight, and links with high latency or packet loss. It runs over UDP, keeps the screen in sync instead of streaming bytes, and echoes your keystrokes locally before the server answers.
mosh-rs is a Rust port of mosh master (decd9b7, March 2026), wire-compatible with mosh 1.4.0, so that it works with the mosh-server already installed on your hosts.
It adds two things upstream mosh never had: a native Windows client, and scrollback that lands in your local terminal's history.
The Linux release binaries are single static binaries.
Status: pre-alpha. v0.1.0 is the first pre-release: download it from the Releases page and see Install. The Known limitations list says what has been tested and what has not. Every number and every compatibility result in this README was measured, and anything not yet tested is marked as such.
Found a bug or something that behaves differently from mosh? Please open an issue. For security problems, follow SECURITY.md instead.
- Pre-alpha: expect rough edges, and report them in the issue tracker.
- The v0.1.0 macOS client cannot connect (an address lookup bug on macOS, fixed on main); the v0.1.0 macOS server works. Use v0.1.1 or later on a Mac.
- Windows: sleeping and waking the machine, Ctrl-^ Ctrl-Z, and idle CPU have not been tested; losing and regaining the network has.
- mosh-server is Unix-only, as in upstream.
- No X forwarding, port forwarding, or SOCKS; mosh never had them.
mosh is excellent software, and its protocol design is the reason this project exists. Its last release, 1.4.0, shipped in October 2022. As of October 2026 the upstream repository has 170 open issues and 62 open pull requests. There has never been a native Windows client; Windows users run mosh inside WSL, Cygwin, or a browser extension. Scrollback has been missing since the start: mobile-shell/mosh#122, "mosh prevents the use of scrollback", has been open since April 2012.
A port keeps everything that works (the protocol, the emulator semantics, the prediction behavior) and makes the two missing features possible without forking the protocol. New features are additive protobuf fields that existing peers ignore, so mixed old and new installs keep working.

- Part of the memory difference is shared-library pages: the C++ binaries load several shared libraries, the static mosh-rs binaries load none.

A mosh session has four layers, and mosh-rs ports each one from upstream.
- Crypto. Every UDP packet is AES-128 in OCB3 mode with a 16-byte tag, keyed by a secret the server prints once over ssh.
- Transport (SSP). Each side keeps numbered snapshots of a state object and sends only the diff from the snapshot the other side last acknowledged, so a lost packet is replaced by a newer diff instead of being resent, and the server adopts a new client address on the first valid packet from it (roaming).
- State objects. The client sends keystrokes and resizes; the server sends its terminal screen, encoded as the escape sequences that redraw the client's copy.
- Frontend. mosh starts mosh-server over ssh, mosh-server runs your shell in a pseudoterminal, and mosh-client draws the mirrored screen plus predicted local echo.
local machine remote host
+--------------+ UDP: AES-128-OCB3 + SSP diffs +--------------+ +-----+ +-------+
| mosh-client | <-----------------------------------> | mosh-server | <-> | pty | <-> | shell |
| (prediction) | keystrokes -> <- screen diffs | (emulator) | +-----+ +-------+
+--------------+ +--------------+
^ ^
+------- mosh launcher: ssh host -- mosh-server new ---+ (once, to exchange the key)
The full design is in docs/ARCHITECTURE.md.
Upstream mosh has no scrollback because the client switches the local terminal to the alternate screen and the server discards rows that scroll off.
With mosh --scrollback and a mosh-rs server, the server records every row that leaves the top of the screen, and the rows on screen when a program clears it, and sends them as a new protobuf field that upstream peers ignore.
The client writes those lines into your terminal's normal history, so the mouse wheel and your terminal's search work as they do over ssh.
Full-screen programs like vim and less run in your terminal's own alternate screen, so nothing they draw enters history and the screen from before them comes back when they exit.
The screen is always current; history follows a few seconds behind on a large burst (the history of seq 1 50000 arrives in about 9 seconds on loopback), because the server sends at most a few packets of history per round trip so that it survives packet loss.
The remote program is never paused for history: if more than 32 MiB of history is waiting (for example while your laptop sleeps during a long build), the oldest undelivered lines are dropped and a dim line in your history says how many.
Known limit: changing the window height can lose or repeat a few rows, because terminals keep the bottom of the screen on resize while mosh's emulator keeps the top.
Against an upstream server, --scrollback falls back to normal mosh behavior and shows a notice.
How this is checked: tests/scrollback.sh runs seq 1 50000 through mosh in tmux with a 200,000-line history and compares the captured history with seq line by line, also through 30% packet loss, around vim, less and clear, across resizes, and against an upstream server.
The Windows client puts the console into VT mode, so keys arrive as the same escape-sequence bytes a Unix terminal produces and output is plain VT bytes, with no key translation layer.
It starts the server with the ssh.exe that ships with Windows 10 and later, and assumes TERM=xterm-256color when TERM is unset, as it normally is on Windows.
mosh.exe and mosh-client.exe cross-compile from Linux and need only system DLLs.
mosh-server stays Unix-only, as in upstream.
The escape key is Ctrl-^, as in upstream; in Windows Terminal you type it as Ctrl+6.
So Ctrl+6 then . quits the session.
Tested by hand on a Windows machine in Windows Terminal against a Linux server (INTERVENTIONS.md): connecting, typing, ls --color, vim, UTF-8 output, Ctrl-C, resizing and quitting all worked, and a session survived turning Wi-Fi off and on.
The Wi-Fi off-and-on test was accepted as the network-loss check for the Windows client in place of a sleep-and-wake test, because both cut the network under a live session and mosh recovers from either the same way.
Sleeping and waking the Windows machine has not been tested.
Not tested yet: Ctrl-^ Ctrl-Z and idle CPU on Windows.

Parsimony
Existing benchmarks measure solve rate and cost, but don't punish excess code, which makes a codebase harder to work with in the long term. Parsimony measures how much code AI models add.
It takes the patches that benchmarks already publish and counts coding units: syntax elements like statements, calls, comparisons, names and literals. Lines aren't counted, so cramming code isn't rewarded, and deleted code is subtracted: net units = added − removed.
